# Runtime and verification boundary

`inspect` uses external pdfplumber for text, tables, images and word counts and pypdf for metadata, page geometry and fields. `audit` records hard parse/page/geometry failures and review warnings. It has no visual detector. `render` uses an actual external renderer, decodes every PNG with Pillow, and checks image count against the PDF page count. It returns the actual executable path and kind. A renderer exit failure is never success.

`build` executes one task builder and structurally audits its actual output. `merge`, `split` and `rotate` use pypdf; outputs are exclusively created. `forms-fill` preserves the canonical AcroForm tree and generated appearances and checks stored field values. Input bytes are preserved. The scaffold uses ReportLab flowables with explicit typography and pagination, registers a selected TrueType font, and otherwise references Base14 Helvetica. Check glyph coverage before adding multilingual text.

Run `python3 scripts/test_pdf_tools.py` from this skill directory for real structure/text/pagination/rotation/AcroForm tests. Set `PILOTDECK_PDF_RENDERER` to a separately built `mutool` or installed `pdftoppm` to include actual rendering tests. These external runtimes are not vendored by the helper. Installation is explicit through `fix`, uses a private venv with source-only pip requirements, and may reuse external site packages; renderer installation is separate. Source-built MuPDF remains subject to its own upstream licensing obligations; this resource does not relicense or silently bundle it.
