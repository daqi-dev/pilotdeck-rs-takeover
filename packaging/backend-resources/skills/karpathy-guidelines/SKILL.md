# karpathy-guidelines

State the behavior to change and inspect the code that owns it. Choose the smallest coherent design that handles the actual inputs. Surface material assumptions before they determine the implementation. Preserve unrelated behavior and avoid opportunistic abstraction. Verify a failure case as well as the intended result. Report what was tested and what remains unverified, including any implementation limits.
