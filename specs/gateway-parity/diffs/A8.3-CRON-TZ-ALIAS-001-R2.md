## 类别

更正（差异已不成立）。原条目与 R1 把「宿主系统树缺 legacy 别名 zone 的 TZif 时
Rust 算不出日期」归为不可避免，前提是「不内嵌 tzdata 规则」这条约束。接手分支
`dev/takeover` 在 2026-11-12 的提交 `487a2b48b` 里放弃了这条约束：时区名改从
随二进制内置的数据解析（`jiff-tzdb` 0.1.4，tzdb 2025b，另补 ICU 独有的名字），
不再读宿主的 zoneinfo 树。差异因此消失，本条不再是已接受差异。

## 基线依据

同原条目与 R1：固定基线 cc7c4e6、Node v22.22.0 / ICU 78，cron 的时区计算走
Node 自带 ICU，不需要宿主 zoneinfo 树上的任何文件（R1「基线依据」第 2 点的
受限树与 sandbox 实测）。本次没有新的基线结论，只是 Rust 一侧向它对齐。

## Rust 行为

`src/pilotdeck-transport/src/named_zone.rs` 按名字从内置数据取规则；
`src/Cargo.toml` 锁定 `jiff-tzdb = "=0.1.4"`。宿主有没有 `tzdata-legacy`、
有没有 backward 链接都不再影响结果：`US/Pacific`、`Asia/Calcutta`、
`Europe/Kiev` 这类别名与基线一样算得出日期、建得出任务。R1 描述的
「create / update 抛 `Cron schedule does not produce a valid future run time.`」
在「宿主缺 tzdata」这个来源上不再发生；「表达式非法」「366 天内永不匹配」两个
来源不变。

## 范围

作废的是：原条目的差异本身，以及 R1 对它在 create / update 面和启动恢复面上
失败形态的描述（R1 里「缺 tzdata 的宿主重启后得到无 `nextRunAt` 的 scheduled
任务」这一场景也随之不再出现）。

不属于本条、仍然没对齐的：进程本地时区（`TZ` 环境变量、`/etc/localtime`）的
建模只对对拍场景里用到的若干取值有依据，POSIX 规则串等没有建模，记在
`state/issues.md` 第 3 级。内置数据的版本（tzdb 2025b）与基线 ICU 78 自带的
规则版本若在某个 zone 的近期规则上不同，会表现为新的差异；目前的对拍场景没有
发现，没有逐 zone 比过。

## 机器判据

黑盒对拍（`scripts/bbx`，同一场景先后喂给基线和 Rust）：

- `cron-create-legacy-zones`：用 legacy 别名 zone 建 cron 任务。
- `tool-get-current-time-legacy-zones`：时间工具对同一批名字的输出。
- `time-process-tz`：进程本地时区的若干取值。

cb8（Ubuntu 24.04 aarch64，没有装 `tzdata-legacy`，即原条目所说会出差异的
那类宿主）上 2026-11-13 对提交 `6894f3dca` 的全量对拍里，这三个场景都是一致
（`~/ws/pdrs-takeover/logs/bbx-v17.log`；汇总在 `state/status.md`）。
复算：`node scripts/bbx/check.mjs cron-create-legacy-zones tool-get-current-time-legacy-zones time-process-tz`。

R1「机器判据」里绑在旧行为上的两个单测：`zone_resolver_failure_fails_closed`
还在（`src/pilotdeck-gateway/src/runtime/cron/schedule_tests.rs`，它注入的是
resolver 构造失败，与宿主树无关）；`resolver_rejects_zones_the_host_tree_lacks`
已不存在。两者现在各断言什么，本更正件没有逐个核对。

## 批准记录

未经人单独批准本更正件。依据是 2026-11-10 起接手分支的授权：范围内的取舍由
接手会话决定、事后汇报（`state/takeover.md`「人已定」）。「时区名改用内置数据、
推翻不内嵌 tzdata 的旧决定」已记在 `state/takeover.md`「需要人过目的决定」表里，
等人过目。本更正件不增加判分豁免，而是撤掉一条：这三个场景按一致
计入，不再以本条为由放过任何差异。
