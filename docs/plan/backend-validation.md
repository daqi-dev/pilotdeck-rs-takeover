# 核心后端分层测试与缺陷处理计划

本计划落实 2026-11-13 用户要求：按完整任务成批发现问题、统一分级处理，将时间优先用于严重缺陷。范围与最终验收仍以 `backend-completion.md` 为准，StaffDeck 延期。**当前执行状态唯一入口仍为 `state/backend-handoff.md`**；本文件规定方法，不重复维护“当前全绿”等状态。

## 两条独立评价线

1. **后端可靠性**：相同输入及模型响应下，协议、工具、权限、副作用、持久化、取消、恢复和发行包是否正确。主要使用确定性本地 provider 与录制响应，先排除模型波动。
2. **真实任务质量**：真实模型能否理解材料、选择工具并交付正确结果。使用少量合成业务任务和公开 Bench 子集，评估数值、约束、报告语义与来源。模型给出错误答案仍是任务失败，但不能自动归为 Rust 缺陷。

每个任务同时报告这两条线。对于合法并发事件，按会话、轮次、步骤和工具调用身份检查因果约束；不把日志固定行号当事件身份，也不全局排序掩盖顺序错误。例如，销售 JSON 数值正确但中文报告错误，不能算任务通过；也不能仅因报告错误修改后端协议。只有真实 provider 运行才计真实模型成绩；录制响应回放不计新增模型能力成绩。

## 执行分层

| 层 | 目的与固定输入 | 执行时机 | 失败处理 |
|---|---|---|---|
| L0 环境与装置前置 | source/bin/driver/fixture 身份、隔离 HOME、实际 projectKey/General 工作区与输入绑定、短 Unix socket 路径、实际组件供给、端口、磁盘、判据负控 | 每批一次，不运行每个 case 前重复全套 | 关联组标 INVALID/未执行；修前置，独立组继续 |
| L1 核心用户任务 | 下表最多 12 个场景族，基础与组合任务；显式区分实际执行 profile 数 | 当前先完成一次广度优先批次；改动后只跑受影响族 | 批内独立项继续，统一收集和聚类；安全/数据失控例外立即停 |
| L2 生命周期与副作用 | 对已有任务定点注入 deny、cancel-after-commit、断线、进程重启、热禁用；不重新发明业务数据 | 选每类风险一个代表，不与平台/模型/渠道做全笛卡尔积 | 先排权限、数据、重复副作用、失控资源等高优先缺陷 |
| L3 必需兼容与发行 | 固定 TS 对拍、所有适用正式场景、声明平台 fmt/clippy/nextest/doc、实际 core/full/addon 搬迁 | 开发期定向；产品候选稳定且高优先缺陷关闭后跑最终全门 | 不把 L1/L2 通过当作豁免；首败保留，独立项 no-fail-fast |
| L4 真实模型与外部任务泛化 | 少量真实模型业务任务；公开 Bench 固定子集、原验证器或明确标识的改编验证器 | 确定性主链和任务沙箱/权限前置通过后执行；不随每次小修重跑 | 模型质量、基础设施错误、后端错误分别归因；首尝试保留 |

L0 的检查不是无穷审批清单：直接复用现有 source manifest、release verify、隔离 wrapper 和组件记录。相同根因导致的多个失败只计一个缺陷簇，仍保留受影响用例数量。

## 首轮任务池：按风险选样，不穷举组合

下表是调度上限和选择依据，不代表已经具备所有 driver 或已经执行。已有五项业务数据位于 `scripts/smoke/backend-journeys/data/`；九条纵向路径详见 `_tmp/20261113-global-delivery-review/journeys.json`。

| 场景族 | 数据等级 | 必验真值/风险 | 首选执行方式 |
|---|---|---|---|
| 销售核算与解释 | 基础 | 金额、地区、退货解释、输入不变；结构正确不等于报告正确 | 已有业务数据；确定性回放 + 少量真实模型 |
| 采购预算与到货约束 | 组合 | 整包数量、预算、期限、延期项；不能只优化最低价格 | 已有自造数据与独立计算真值，需核 runner 支持 |
| 续费报价与重启续轮 | 状态/恢复 | 折扣只来自旧会话，真实换 PID，第二轮不重塞旧条件 | 已有真实模型原件及发行包离线回放 |
| 审批拒绝后的停止 | 权限/副作用 | 实际 permission deny；目标字节不变，不换工具绕过 | 优先已有权限正式场景；独立业务 manifest 的专用 driver 尚缺 |
| 入账提交后取消与恢复 | 数据/副作用 | durable 后取消，owner 退出，账目与调用次数都恰一次 | 已有自造数据；补最小确定性控制，不能只观察输出一行 |
| 核心渠道任务与热禁用 | 生命周期 | 入站→模型→权限/工具→真实回信→历史；旧代连接收口 | 已有 core recovery、Feishu normal/stop |
| 外部执行与恢复 | 部署/恢复 | stdio 归属；TCP 同长期 sidecar、不重复副作用、身份关联 | 原主链分别一个 stdio/TCP profile；不重复已过相同身份 |
| SDK 插件与子代理 | 隔离/代际 | 目录能力生效、父子与会话隔离、替换/clear/释放 | 既有 directory、fork 正式输入；后续缺口定向补 |
| 自动化触发与停止 | 生命周期 | cron/always_on 真执行、更新、取消、重启；不能空场景 SAME | 两种模式分别报告；先核预置任务与实际 provider 命中 |
| 模型协议工具续轮 | 协议/组合 | Chat、Responses、Anthropic、Google 的真实请求→工具结果→终态 | 复用已覆盖 Chat；其他按模式最少一个，不伪造 Responses 正式入口 |
| 文件资料与可交付产物 | 组合/发行 | grep/read、PDF/image/Office 真实内容、缺组件明确失败、默认资源加载 | 搬迁后的包；外部 runtime 的来源与身份纳入结果 |
| 公开 Bench 固定子集 | 泛化 | 陌生输入的确定性最终状态、禁止副作用、模型真实决策 | 先选少量本地文件任务；独立于项目自造数据计数 |

**场景族、profile 和实际运行次数分别计数。** 例如一个外部执行族的 stdio/TCP 是两次运行，不能报成“一次覆盖所有部署”。平台与所有模型的完整组合留给明确必需门；探索批不做 12×平台×模型×部署的乘法。

## 每个 case 的最小记录

复用现有 manifest/capture/receipt，而不是另建一套运行平台。批次清单补充以下字段即可：

- 固定 case ID、来源版本/文件 SHA、许可、数据等级、风险标签、声明的 profile。
- 输入文件、初始持久状态、权限策略、允许的外部服务、完成条件和禁止副作用。记录实际 Gateway 工作区；进程 cwd 不等于项目绑定，General 使用隔离 PILOT_HOME，输入必须放在该任务实际可读的根。
- 独立真值：结构化数值/约束、原文件 hash、调用次数、真实 permission/cancel、前后进程身份、恢复历史、终态及资源收口。业务解释按已列事实核对；LLM judge 不能独自关闭金额、权限或数据安全问题。
- source/bin/driver/model 身份，首次运行原件，时间与 API/token 用量，pass/fail/invalid/blocked/not-run。
- 若失败：严重度、归因类别、证据确信度、共享根因簇、受影响入口、下一动作和负责人。

公开任务的答案、verifier、参考解法不放进被测模型可读项目。先冻结选择规则与清单再看模型成绩；用例调整须留下原因及旧结果。改编任务报告 adapted subset，不使用官方排行榜分数。

## 缺陷分级：严重度与原因分开

此处 P0/P1/P2/P3 是缺陷优先级，与交付计划的同名里程碑不同。

| 级别 | 判定 | 处理规则 |
|---|---|---|
| P0 | 越权、敏感数据外泄、丢数据、不可控或重复副作用、核心服务失控且无法正常收口 | 立即停止受影响执行，先保存原件并收束自有资源；优先修复，不继续耗费真实 API |
| P1 | 正常核心任务/必交部署模式无法完成；恢复失败；声明发行能力依赖未声明参考仓；必需行为明确缺失 | 当批独立项继续完成，随后优先解决同根因簇；未关闭不得交付 |
| P2 | 有限边界不兼容、可绕过且不涉及数据/权限的缺陷、测试 oracle/装置或配置问题 | 批后合并处理；同一环境前置错误先止住关联组，不为每条报错创建产品修复 |
| P3 | 无功能影响的文案、日志、低价值整洁项 | 登记并后排；不能因此拖住高优先工作 |

原因另标 **Product / Harness / Environment / ModelQuality / Unknown**。它与严重度正交：例如测试器漏判越权也可以是 P0 Harness。未证实原因必须保留 Unknown，不能用“重跑绿”改成环境抖动。

进入产品修复队列需要：实际输入/原始证据、明确产品合同或固定 TS 冲突、受影响范围。修判据需要独立证明原判据错且负控仍能抓错。环境问题先修供给/隔离，不修改产品行为。模型质量问题保持业务 FAIL，使用相同录制响应或已固定请求做最小对照，再判断后端是否参与致错。

## 批量发现与修复节奏

1. **预声明一批并冻结身份。** 只运行 ready 的独立项，缺 driver/环境的项明确 not-run；不临时替换成容易通过的任务。
2. **先完成独立批次。** 除 P0 或共同环境前置失效，不因单条 first-fail 中断整批、临时派多人深挖；最多先做识别共享根因所需的短诊断。
3. **集中聚类。** 依据失败阶段、错误签名、共享依赖和同一源码身份聚成缺陷簇。区分十个失败用例与十个产品缺陷；不把全部 FAIL 合并成一个总百分比。
4. **按风险排修。** P0 → P1 → 阻断下一批的 Harness/Environment → 其他 P2/P3。同级优先影响入口多、复现明确、修复能解锁更多验证的项；不按哪个最容易改来选。
5. **每簇限一个负责人和一个独审。** 首轮诊断目标是分类与最小复现，建议 20 分钟内给出结论或明确 Unknown。超过后回到根协调排程，不自行扩大边界矩阵。
6. **定向关闭。** 保存首败 → 同代表 case 通过 → 必要负控仍拒 → 受影响组通过。没有新公共变更，不反复重跑整个 workspace。
7. **冻结最终候选再跑全门。** 无未处理的 P0/P1、必需模式已运行、环境已校准后，再做双平台全量/完整适用对拍/搬迁/性能。探索批通过不等于最终交付。

当前无须新建测试平台。第一轮先利用现有 bbx、五项业务数据、原恢复/cancel 驱动与 release verify；只有一个必需入口无法表达时才补最小适配。确定性批次不新增真实消费。真实模型累计预算以统一账本和交接为准，每批另列固定任务、模型、调用/token/时间上限，保持首尝试成绩；不自动重试到成功，也不把录制 usage 当新消费。

## 防止测试适配本身变成局部修补

公开 Bench 的适配必须保留任务所需能力：代码/文件任务允许在隔离工作区创建中间文件和运行原环境具备的计算工具；通过隔离边界限制宿主、密钥与 verifier 访问。只允许最终输出文件、却禁止完成任务所需的中间操作，会改变被测问题。此类首失败保留并分类，停止继续付费调参数；具备代表性环境后才开始独立新尝试，不把旧失败改称通过。

真实 API 前先用现有本地 provider 做一次完整请求角色校准，覆盖 title、router classifier、主 agent 和必要的 count 请求。工具声明限制只在对应角色生效；合法的无 tools 分类请求不能被当成主 agent 越权。角色须由真实请求合同识别，不能只用“不是 title”推定。

装置连续出现两个独立前置失败时，先暂停关联执行，集中核一次输入闭包、源码身份、真实运行环境和后置判据，再安排整批；不每修一处就付费或全量重跑。测试合同、身份守卫和资源闸门保持有效，修复必须指向已证实的根因。对判分冻结的修订仍依仓库原规则办理。

## 收口时复用哪些证据

按原交付计划的五层完成条件核证据，避免把探索批自行扩大成额外交付要求：

- 每个渠道仍须证明其生产配置接线、认证、独有协议和实际入出站。共享宿主的权限、工具、重启与回收可复用代表性组合路径；不要求每个渠道重跑一遍相同的完整 CLI 旅程。
- 自动化的 timer、更新、停止和持久恢复可由身份明确的实际场景共同证明，不强制新造一次包含所有操作的组合 driver。
- Office 深层结构、渲染和重算结果按相同源码与引擎身份复用。最终包只补安装位置、默认发现、依赖供给和相对路径的实际接线差额，不为每种格式再建真实模型任务。
- Addon 必须有安装映射后的真实调用；原已通过的 browser 动作矩阵与 ASR 推理按来源身份复用，不把自然会议准确率 Bench 纳入核心发行门。
- 跨包组合、适用的切换/重启/回滚按原承诺验收；不将它扩成所有历史版本升级迁移。某项升级兼容被明确承诺后，才新增对应 old/new 验证。

这些复用原则不降低冻结判据，也不把旧候选成绩转记到新候选。变更影响与最终完整门仍分别记录。依据及当前原证见 `_tmp/20261113-acceptance-cost-review/review.md`；该报告是本次排程审计，当前状态仍维护在统一交接。

实际批次、当前候选和后台任务只在 `state/backend-handoff.md` 维护；根因簇、首败、修复验证和下一动作在 `state/backend-validation-failures.json` 维护。已通过的相同身份主链仅在变更影响或里程碑要求下重跑；计划本身不构成任何场景已执行或已通过的证据。
