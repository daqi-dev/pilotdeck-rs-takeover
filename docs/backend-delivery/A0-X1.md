# A0 / X1 原生扩展与装配

起点：`e8702d36c82cd5fa030d5e8ba3e724b0bfa68c95`。负责人：主协调者；R1 配合 native factory 与子代理传递。交付提交：待首候选集成。

当前状态：进行中（接口、实现和正式嵌入接线已实现，独立消费验证与发行仍未完成）。

公开接口在 `pilotdeck_gateway::extensions`：`NativeExtensions`、`NativeExtension`、`ExtensionRegistration`。`LocalGateway::start_with_extensions` 使用正式装配路径，`LocalGateway::shutdown` 排空会话与资源。工具复用 `ExecutableTool`，路由复用 `CustomRouter`，执行工厂复用 `ExecutionFactory`，提示附加到正常会话提示。没有 JS 加载器、动态库 ABI 或全局注册表。

`register(id, project, extension)` 注册一代；`update` 原子替换；返回的所有权 token 必须保留，`unregister` 或 drop 只卸载它自己的代际，不会误删同名新版。项目范围使用规范绝对路径；会话快照按项目和会话 key 固定，更新只影响新会话。已有会话持有旧代的工具、路由、提示、factory 与 `resources`，最后释放时走 Rust `Drop`。扩展无法绕过工具权限。工具名/别名与内置、MCP、子代理、对话工具冲突会明确拒绝会话装配。

独立消费者：`src/pilotdeck-gateway/tests/native_extensions.rs`，只使用公开 API，在隔离目录登记项目，使用本地 mock provider 与真实 native Agent 循环，自定义 factory 包装正常执行器，验证工具调用、提示、旧会话/新会话代际、卸载、同名冲突与 shutdown 释放。核心注册表测试另覆盖项目隔离与可重入工具描述符。

## 独立审查

E0 工作者指出并经复查关闭：

1. bind 持锁调用工具的 `fields()`，扩展可重入时自锁。现在 publish 在锁外验证并固化工具名，bind 只使用元数据。
2. extra_tools 注册错误被忽略，扩展同名工具会静默消失。现在 `with_native_tools` 先对完整会话工具目录做注册验证，失败返回明确错误。
