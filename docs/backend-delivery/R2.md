## 实现与协议边界

`HostClient::connect_tcp` 连接真实 TCP socket，开启 no-delay，校验地址和端口，单独应用连接期限；默认 5 秒，沿用 Node 定时器超过 `2^31-1` 毫秒归一到 1 毫秒的既有兼容语义。握手仍由独立可选 handshake deadline 管理。`TurnHostFactory` 的 TCP 分支已经接线，主会话和子代理使用 R1 的统一选择规则及项目 implementationId 校验。

连接恢复复用现有 `host/recovery.rs`，替换的只有 socket。保持原执行身份、accepted stream、事件队列、回调响应缓存和总字节预算；新连接握手必须确认同一 moduleInstanceId，resume 携带旧 connectionGeneration 与已接受游标。不会重发 execute；重复 module callback 返回原缓存响应，不再次执行工具效果。只有对方同时声明 execute streaming resume、resume 和 ack 能力时才允许恢复，最多替换一次连接。不同实例、流身份改变、无恢复能力或恢复失败均明确失败。

stdio 仍由宿主管理子进程和进程组。正式部署使用普通 `spawn`，不会通过重启一个普通 sidecar 假装同实例恢复；既有显式 `spawn_resumable` API 只供能够接回同一保留实例的程序使用。

基线依据：`src/agent/modules/transport/tcpAgentLoopSidecarConnection.ts:10-178` 的 TCP 连接/关闭/重连；`agentLoopSidecarClient.ts:848-928` 的旧 binding、resume 游标、单次恢复及实例约束。参考目录只读。

## 未闭合项

第二候选实现的是 Gateway 消费外部 TCP 模块及其恢复能力。Rust 自带 `ExecutionServer` 自报 resume=false/ack=false；独立 Rust sidecar 仍只有 stdio 入口，没有可跨 socket 保留 stream 的 TCP server。不能把 TCP 客户端恢复测试等同于自带 sidecar 的 TCP 发行验收。

下一批已实际取证：固定 TS 正式 CLI 构造默认 `AgentLoopSidecarServer(factory)`，即使启用 TCP 也自报 resume=false/ack=false；source API 显式配置才开放恢复。`_tmp/20261113-R2/oracle/cli-{first,second}/observations.json` 两次正式入口结果相同：不同 socket 共享实例、更换 connectionGeneration；resume/ack 分别返回 RESUME_UNSUPPORTED/ACK_UNSUPPORTED。固定 TS 基线 4 项相关测试也实际通过，产物 `baseline-selected.tap`。新 `pilotdeck-transport/src/tcp/` 正在实现原生监听器及显式可选 ACK/回放，尚未 mod 接线或编译；默认能力保持基线，不能先广告未验证能力。保留同一执行引擎和精确待答回调，不通过再次 execute 恢复。

## A0/B1 原生组合接口

配合 SOP 组合新增源码级接口，不增加 wire 字段或操作：

- `ExecutionContext::with_event_filter`：作用域内过滤中间事件，支持嵌套和 panic 恢复；被过滤事件不占用 sequence，控制检查和 OriginalAgentFactory 的 accepted uncertainty 检查保留，owner 的最终 terminal 不被过滤。
- `TurnHostFactory::with_port_decorators`：包装每轮新建的 model/context/tool_execution，回调收到真实 ExecutionIdentity；元数据、落盘、上下文状态和代际资源仍由原装配持有。
- `TurnHostFactory::with_durable_message_observer`：选定消息由原 Recorder 成功提交后调用 observer，成功后才 yield；普通会话维持原顺序。取消一次 next 等待不重启 observer。落盘或 observer 失败沿用 callback_error、取消及失败终态，业务模块不直接写 Recorder。

对应新增测试为 `pilotdeck_transport::server::event_filter_tests` 和 `runtime::turn::live_stream_tests::selected_durable_observer_commits_before_visibility_and_survives_cancelled_wait`。测试源码覆盖连续序号、作用域恢复、取消不能被过滤、持久成功门、等待取消与失败路径；本轮定向测试已通过，固定候选质量门禁仍待执行。

## SOP 节点宿主（第二候选后，验证待完成）

新增 `native_process/sop_nodes.rs`，使用正式 `ProjectSessionFactory`、`FactoryStorage` 和 `TurnHostFactory` 创建内部节点。节点路径按父真实 transcript 的侧链目录确定；精确校验 parent/skill/node 与 session/sidechain ID，恢复 `parentSessionId`，异父拒绝 `SOP_NODE_PARENT_MISMATCH`。每个节点缓存自己的 handle、历史与 context，但每轮 native factory/decorators 运行完成后清空，避免 SOP runtime 的 Arc 环。节点消息由自己的 Recorder 提交后经父 host event buffer 转发，父 transcript 只记录最终 SOP 回复。取消等待会中止节点并由独立任务 drain 到流结束；关闭等待节点 writer 与资源释放。

正式 TS `new_session` Hook 实测证据为 `_tmp/20261113-B1/sop-nodes-hooks-self-1/{ts-hooks.json,ts-self-hooks.json}`：父 SessionStart、Setup、UserPromptSubmit 各一次，两个父 PreModelRequest，最后父 SessionEnd。节点宿主因此过滤重复会话 Hook，并把模型/工具生命周期委托给父绑定（保留节点协议与审计身份）；节点权限问答和 user-dialog 也沿父 Gateway channel 返回。第三批新增存储恢复、异父拒绝、取消/drain、Hook身份及租约定向测试已通过；正式节点 CLI 首次输入封装、第二次事件来源失败已保留并修复，第三次 `new_session/hooks/receipt` 及 correction 正式复验通过，详见 R1 末段。恢复场景与固定候选门禁由主协调者继续汇总。
