## 当前实现及接线

`pilotdeck server` 与本地 CLI 使用 `TurnHostFactory`。默认 `Deployment::Native` 直接在 Gateway 进程内运行现有 Rust `ExecutionServer` / `OriginalAgentFactory`，通过有界内存管道复用宿主能力协议，未启动子进程、不寻找 sidecar 文件。独立 sidecar 仍保留，显式 stdio 才启动它。

公开的 `select_loop(snapshot, env, cwd)` 返回 `LoopSelection { deployment, expected_module_id }`；启用的项目 `modules.agentLoop` 先于环境 fallback，项目 implementationId 用于握手校验。主会话、一次性子代理及可续写子代理传递相同选择，并使用自己的项目资源。外部部署保留模块消息标记与 operation ledger；只有 native 省略外部模块标记。

`TurnHostFactory::with_native_factory` 和 `HostClient::native_with_factory` 接受 Rust `ExecutionFactory`；`SubagentRuntime` 的同名 builder 把工厂传给两种子代理。显式 stdio 不应用 Rust 工厂。

`PreModelRequest` / `InstructionsLoaded` 仍异步运行，但收到原始用户取消信号。普通轮次的 hook 绑定清理使用另外的信号，因此正常完成不取消这些 advisory hooks。首候选 `50cfd7c96633de7dbfdf8159d3934eefd9d55262` 之后的所有权审查发现：idle session 关闭及前轮遗留 Hook 尚未进入关闭链。本批后续新增 `SessionHookCleanup`，跟踪每个会话所有在途 dispatch 的原始取消信号，关闭时同步取消并等待 runtime 释放；已由 assembly 的 prepared-resource 释放链接入。后续修改仍待固定提交验证。

上下文审查确认：prompt cache/time 和 compaction cooldown 原已随 `SessionTools` 保存；`ToolResultBudget` 和 `PromptContributionRegistry` 却每轮重建。本批后续将后两项移入既有 `SessionContextState`，按 spill 目录区分作用域，在同一会话内跨轮保留引用与贡献代际，随会话释放；model handler、轮次取消信号及项目代际租约仍每轮构造。

## 基线及明确差异

- TS：`src/cli/AgentLoopDeploymentProfile.ts:44-127` 的环境与项目选择；默认 native、项目绑定 implementationId、stdio/TCP 的不同所有权。
- TS：`src/agent/loop/AgentLoop.ts:699,2281,2843` 的 advisory 生命周期与 `input.abortSignal`。
- 发行差异：默认 stdio 命令为随发行包提供的 Rust sidecar，不再隐式加载 Node/JS；显式 command/path 仍可配置。
- 内存管道保留序列化边界；本批未声称消除序列化开销。
